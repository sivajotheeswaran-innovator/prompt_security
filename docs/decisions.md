# Architectural & Design Decisions

This document records key decisions made during implementation when addressing ambiguities or design choices, per `docs/agent-rules.md`.

## Decision Log
- **Setup (Phase 0)**: Initialized project repository with standard modular structure (`frontend/`, `backend/`, `docs/`, `.agents/skills/verify-phase`).
- **Phase 1 (Database Connection Resilience)**: Configured PostgreSQL with `pg.Pool` for Supabase connection via `DATABASE_URL`. Provided an in-memory PostgreSQL engine fallback (`pg-mem`) when credentials are omitted, guaranteeing instant local offline testing and self-contained CI/acceptance runs while retaining full PostgreSQL DDL and query compliance.
- **Phase 1 (Policy Auto-Creation)**: Auto-creates a default `'balanced'` row in `policies` table during user registration (`POST /api/auth/register`) and ensures idempotency with `ON CONFLICT (user_id) DO NOTHING`.
- **Phase 1 (Security & Validation)**: Implemented strict Zod schemas for `/auth/register`, `/auth/login`, and `PUT /policy`. Password validation enforces minimum 8 characters. Enabled Helmet security headers, CORS origin matching, and 200 req / 15 min rate limiting.
- **Amendment 1 (Database Pooler & SSL)**: `DATABASE_URL` targets the Supabase transaction pooler (port 6543) with `ssl: { rejectUnauthorized: false }`. Documented in `.env.example`.
- **Amendment 2 (Layer 2 Contract & Offset Computation)**: Gemini receives text already masked by Layer 1 and returns `{type, text, confidence, explanation}` with zero index offsets. The backend securely maps `text` back to the original prompt via `indexOf`, discards spans overlapping Layer 1 detections, and computes `start_idx` and `end_idx` authoritatively.
- **Amendment 3 (Audit Trail Integrity)**: `scans.redacted_prompt` always persists the fully masked prompt across all actions (`allow`, `redact`, `block`), preventing sensitive data leakage into database audit logs even when clean/low-risk prompts pass through.
- **Amendment 4 (Prompt Injection Policy)**: Classified `prompt_injection` as `high` severity (+30 risk score bonus). Strict and balanced modes mandate an automatic `block`. In relaxed mode, the prompt is permitted through but flagged with `injectionWarning: true`.
- **Amendment 5 (Single-turn Chat Gateway)**: `/chat` operates strictly single-turn with no conversation history sent upstream to Gemini, eliminating history exfiltration vectors. Conversation history is retained purely in client-side React state.
- **Amendment 6 (Gemini SLA & Fallback)**: Gemini invocation timeout clamped to 10s with thinking disabled (`thinkingBudget: 0`) to minimize latency. On timeout or API error, gracefully degrades to Layer 1 regex/checksum findings (`ai_layer_ok: false`) without failing user requests.
- **Amendment 7 (Proxy Trust & Scoped Queries)**: Enabled `app.set('trust proxy', 1)` for accurate rate limiting behind reverse proxies. Scoped all database access strictly by `user_id`. Aggregated `/stats` `byCategory` directly with `GROUP BY findings.type`.
- **Amendment 8 (Detector Precedence & Overlap Resolution)**: Checksum-validated detectors (Verhoeff for Aadhaar, Luhn for credit cards) outrank pattern-only regexes. Conflicting overlapping spans are resolved by retaining the higher severity finding (tiebreaking by higher confidence).
- **Amendment 9 (Standardized NPM Scripts)**: Standardized scripts in `backend/package.json`: `dev`, `build` (`tsc`), `start` (`node dist/server.js`), `test`, and `migrate`.
- **Amendment 10 (Frontend Base API URL)**: Configured `VITE_API_BASE_URL` in `frontend/.env.example` to explicitly include `/api`.
- **Phase 3 (Chat Gateway & Lifecycle Redaction)**: Implemented `POST /api/chat` with single-turn prompt execution. If policy action is `block`, returns `blocked: true, reply: null` without dispatching an upstream request to Gemini. If `redact`, dispatches only the sanitized prompt with typed placeholders (`[PHONE_1]`, `[PAN_1]`) to Gemini, restores placeholders in the reply, and immediately purges the `RedactionMap` from memory. If `allow`, forwards prompt as-is. All scans are persistently logged in `scans` and `findings` with strictly masked previews and zero raw secrets. Implemented graceful Gemini failure fallback returning a user-friendly notice without crashing.
- **Phase 4 (Frontend Architecture & Live Security UI)**: Built dark security-themed frontend with Vite + React 18 + React Router + TailwindCSS + Axios + Recharts. Implemented `AuthContext` with JWT interceptors, protected routing, and 5 core pages: `/chat` (featuring dynamic risk gauge, live color-coded finding span highlights, and "Gemini Received" transparency toggle), `/dashboard` (Recharts area, donut, and category bar charts), `/audit` (filterable ledger with masked previews and telemetry modal), `/policy` (3 mode cards with live posture switching), and `/redteam` (8 one-click attack vectors pre-filling the chat interface). Verified end-to-end via automated browser subagent.
- **Fix Pass Before Deployment**:
  - **Gemini Mock Elimination**: Removed all mock echo mechanisms (`MOCK_GEMINI`). When key is absent or Gemini fails, `/scan` returns `aiLayerOk: false`, and `/chat` returns clear user-facing fallback with `isFallback: true`.
  - **Database Strictness**: `pg-mem` is now locked exclusively to `NODE_ENV=test`. In `development` and `production`, `DATABASE_URL` and `JWT_SECRET` are required without default fallbacks; startup exits with a descriptive error if missing.
  - **Policy Enforcement**: Any detected finding forces at least `redact` across all policy modes. Policy thresholds decide strictly between `redact` and `block`. Only clean prompts (0 findings) are allowed through as `allow`.
  - **Generic Secret Detector**: Added high-entropy token detector following secret/key/token/bearer labels using Shannon entropy calculations (threshold >= 3.0, minimum 20 characters) to detect arbitrary custom API keys.
  - **Layer 2 Span Coverage**: Layer 2 now masks all non-overlapping occurrences of each returned snippet across the entire prompt instead of breaking after the first match.
  - **Production CORS**: Localhost and 127.0.0.1 origins are allowed only when `NODE_ENV !== 'production'`. In production, only the configured `FRONTEND_URL` is permitted.
  - **Unified Testing**: `npm test` orchestrates all 4 test suites (Phase 1, Phase 2, Chat Acceptance, Live Gemini) with exit code 0 enforcement.
